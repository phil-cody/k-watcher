# Kwork watcher bot

Личный Telegram-бот: следит за новыми заданиями Kwork в выбранных категориях, анализирует
каждое новое задание и присылает **вам в Telegram** краткую оценку и черновик отклика.

Бот **не отправляет отклики** и не выполняет никаких действий от вашего имени на Kwork.

📚 **Подробная база знаний** — [docs/KNOWLEDGE-BASE.md](docs/KNOWLEDGE-BASE.md): архитектура, поток
данных, инварианты, форматы файлов, тексты интерфейса, безопасность, рецепты модификаций,
диагностика.

🚀 **Перенос на сервер** — [docs/DEPLOY-VPS.md](docs/DEPLOY-VPS.md): systemd, логи, бэкапы,
обновление, безопасность, чек-лист.

🤖 **Подключение ИИ-модели** — [docs/MODEL-SETUP.md](docs/MODEL-SETUP.md): выбор бесплатного
провайдера (Gemini, Groq, OpenRouter, локальная Ollama), настройка бюджета запросов,
диагностика ошибок.

✍️ **Все тексты интерфейса** (сообщения Telegram, логи, вывод CLI, черновик отклика) — в одном
файле [config/texts.json](config/texts.json). Правки без изменения кода: см. раздел «Тексты»
в базе знаний и переменную `TEXTS_FILE` в `.env`.

## Что подтверждено пользователем

| Параметр | Значение |
|---|---|
| Разрешённый объём | Только страницы списка заданий `https://kwork.ru/projects` и параметры `c`/`attr`/`page` (категории из каталога) |
| Страницы отдельных заданий | **Не запрашиваются** (вне разрешённого объёма) |
| Частота | Случайная пауза 240–600 секунд перед каждым запросом; первый запрос после старта — сразу, без паузы |
| Параллельность | Один запрос одновременно, последовательно |
| Окно опроса | 05:00–20:00 `Europe/Moscow`; после 20:00 опрос останавливается до утра |
| Пейджинация | По `last_page` из выдачи, не глубже `maxPagesPerUrl` (по умолчанию 6) |
| Категории по умолчанию | Все категории заданий (общий список `/projects`) |

Полный текст подтверждения и список того, что в объём **не** входит, — в `config/default.json`
(`source.permission`). Посмотреть человекочитаемо: `node src/index.js plan`.

## Формат сообщений

Сообщения уходят с `parse_mode=HTML`: заголовки разделов выделены жирным, длинный текст
читается легче. Все значения из задания экранируются, поэтому символы `<`, `>` и `&`
не ломают разметку. Длинное сообщение разбивается на части **по границам блоков**, так
что HTML-теги никогда не разрезаются пополам.

Структура каждого уведомления:

```
🔔 Новое задание Kwork
<заголовок>
Рекомендация: подходит / возможно / не подходит

📌 Факты из карточки
🧭 Вывод
⚠️ Риски
❓ Неизвестно
💰 Предварительные условия
📝 Вопросы заказчику
✍️ Черновик отклика (только для ручной проверки)
```

## Что бот делает и чего не делает

**Делает**
- находит карточки заданий в разрешённом HTML выбранных категорий;
- нормализует id, ссылку, заголовок, описание, бюджет, дату и категорию; отсутствующие поля
  помечает как `null` и перечисляет в `missingFields`, ничего не додумывая;
- убирает дубликаты по стабильному id, ссылке или осторожному составному ключу;
- готовит сообщение с разделением: факты из карточки / выводы / неизвестное, с рисками,
  признаками заниженной цены и вопросами заказчику;
- предлагает черновик отклика **для ручной проверки** — в стиле ваших откликов, с составом
  работ, стеком, ориентиром по цене и сроку и 1–2 уточняющими вопросами;
- считает цену и срок **от вашей ставки** (`pricing.hourly_rate`) и норм времени из профиля;
- присылает уведомления, когда окно опроса открывается и закрывается;
- имеет команды `/start`, `/status`, `/plan`, `/profile`, `/categories`, `/pause`, `/resume`, `/usage`, `/users`, `/help`;
- хранит одно задание под одним ключом (id), поэтому число записей в индексе равно числу задач;
- расшифровывает каждое предупреждение и ошибку цикла отдельной строкой в логе.

**Не делает**
- не запрашивает страницы отдельных заданий, API, поиск, профили и аккаунтные разделы;
- не входит в аккаунт, не использует cookies, токены, прокси, маскировку и обход защиты;
- не отправляет формы, отклики, сообщения и заявки, не меняет данные на Kwork;
- не сохраняет HTML (разбирает в памяти и отбрасывает);
- не ускоряет опрос при ошибках и не обходит 429/CAPTCHA — при них опрос останавливается;
- различает реальную проверку и упоминание: слово `captcha` в подключённом скрипте или в скрытом
  служебном блоке **не** считается проверкой и не останавливает опрос.

## Требования

- Node.js 20.6+ (проверено на 24.15.0). Сторонних зависимостей нет: HTTP, парсинг HTML,
  Telegram Bot API, хранилище и планировщик реализованы на стандартной библиотеке.

## Установка

```bash
cp .env.example .env      # заполните локально, НЕ коммитьте
npm test                  # 321 тест, сети не требуют
```

Секреты задаются только через окружение или `.env`:

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да, для режимов `bot`/`poll` | токен от @BotFather |
| `TELEGRAM_ALLOWED_USER_ID` | нет | ваш числовой Telegram id — вы становитесь владельцем бота; если не задан, владельцем станет первый написавший |
| `TELEGRAM_CHAT_ID` | нет | чат для уведомлений (по умолчанию — из первого сообщения) |
| `MODEL_PROVIDER` | нет | `heuristic` (по умолчанию), `openai-compatible`, `anthropic` |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | при `openai-compatible` | ваш эндпоинт и ключ |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` | при `anthropic` | ключ и модель |
| `DATA_DIR` | нет | каталог состояния (по умолчанию `data`) |

По умолчанию используется офлайн-эвристика: внешних вызовов и биллинга нет.
Платная модель не включается без вашей явной настройки.

## Подключение бота и другие пользователи

**Доступ открыт: достаточно написать боту `/start`.** Подтверждение владельцем не нужно —
подключение нового пользователя просто фиксируется в логах:

```
[info] Новый пользователь подключился к боту {"userId":123456789,"username":"client"}
```

Владелец задаётся в `.env` (`TELEGRAM_ALLOWED_USER_ID`) и видит расширенный набор команд.
Каждый пользователь настраивает **свой** профиль и **свои** категории — общего профиля нет.

Список подключённых сохраняется в `data/telegram-state.json` и переживает перезапуск.
Посмотреть, кто подключён: `/users` (только владелец).

Если нужно закрыть доступ (например, бот в публичном месте) — `config/default.json`:

```json
"telegram": { "autoApprove": false }
```

### Категории у каждого свои

Каждый пользователь выбирает, какие категории Kwork ему показывать. Можно писать **числом
или названием**:

```
/categories                     показать текущий выбор
/categories list [фильтр]       каталог категорий и подразделов
/categories Верстка             выбрать по названию
/categories Вёрстка по макету   выбрать подраздел
/categories 37,38,79            выбрать числами
/categories Дизайн              весь раздел (все его категории)
/categories all                 любые категории (фильтр выключен)
/categories reset               вернуться к категориям по умолчанию
```

**Полный каталог сайта** — `config/categories.json`: 7 разделов, 54 категории,
219 подразделов. Связь с запросами:

| Что | Запрос |
|---|---|
| Категория | `/projects?c=<id>` |
| Подраздел внутри категории | `/projects?c=<id>&attr=<id>` |

Числовой `id` совпадает с полем `category_id` в выдаче заданий, поэтому бот показывает
**название вместо числа**:

```
• Категория бота Верстка (Разработка и IT): Верстка по макету, Доработка и адаптация верстки
```

Обновить каталог после изменений на сайте:

```bash
node src/index.js categories-refresh              # один GET на страницу списка заданий
node src/index.js categories-refresh --file=page.html   # или из сохранённой страницы
```

**Поиск по названию не зависит от регистра и букв ё/е, й/и:**

| Ввод | Что найдётся |
|---|---|
| `верстка`, `ВЁРСТКА`, `Вёрстка` | категория «Верстка» |
| `вёрстка по макету` | подраздел «Верстка по макету» (`?c=79&attr=224`) |
| `доработка и адаптация верстки` | подраздел (`?c=79&attr=226`) |
| `создание саита` | «Создание сайта» (й→и) |
| `Дизайн`, `Разработка и IT` | все категории раздела |

Остальное:

- выбор хранится в `data/categories/<id>.json` и переживает перезапуск;
- фильтрация идёт **до анализа**: задание из чужой категории не тратит ни вычислений,
  ни квоту модели, ни место в индексе;
- id вне каталога тоже принимается — бот пометит его как «своя категория»;
- задание без числового id категории не отбрасывается: лучше показать лишнее, чем потерять;
- в профиле можно указать `categoriesSelection` — при загрузке профиля выбор применится сам.

> **Категории по id.** `?c=37` — **«Создание сайта»**, `?c=38` — **«Доработка и настройка
> сайта»**, `?c=79` — **«Верстка»**. Категории берутся из каталога `config/categories.json`,
> жёсткого списка URL больше нет.

### Профиль у каждого свой

У каждого пользователя **свой профиль исполнителя**: от него зависят вердикт, риски, цена,
срок и черновик отклика. **Общего профиля нет** — пока вы не загрузили свой, задания вам не
приходят, а бот раз в сутки напоминает о загрузке.

```
/profile            показать свой профиль и его источник
/profile upload     загрузить свой профиль (бот ждёт файл JSON следующим сообщением)
/profile template   получить шаблон профиля файлом
/profile reset      удалить личный профиль (общего нет)
```

Профиль хранится в `data/profiles/<ваш Telegram id>.json` и принадлежит только вам.
Путь к файлу в сообщениях не показывается: он у каждого свой и лежит внутри приложения.

Как это работает:

- файл принимается **только** после `/profile upload` (окно ожидания 5 минут) — случайный
  документ в чате игнорируется;
- профиль проверяется перед сохранением: битый JSON или профиль без навыков, портфолио и цен
  отклоняется с понятной причиной, прежний профиль не теряется;
- **каждое задание анализируется отдельно для каждого пользователя**: у одного ставка 700 ₽/час,
  у другого 1500 — цены и черновики в сообщениях будут разными;
- лимит файла — 256 КБ; профиль хранится в `data/profiles/` (в git не попадает).

**Команды владельца** — `/users` и `/usage` — показываются в меню только в вашем чате
(Telegram-область `scope: chat`) и не выполняются для остальных: они получают ответ
«Команда доступна только владельцу бота».

Доступ открыт по умолчанию: любой, кто напишет `/start`, подключается сразу. Если бот
работает в публичном месте и доступ нужно закрыть — `config/default.json`:

```json
"telegram": { "autoApprove": false }
```

### Защита загрузки файла

Загрузка профиля — единственное место, куда попадают данные от других людей, поэтому
проверок там несколько уровней:

| Уровень | Что проверяется |
|---|---|
| Тип файла | только `.json`/`.txt` и MIME `application/json`/`text/plain`; архивы, скрипты и страницы отклоняются |
| Размер | до 256 КБ; пустой файл отклоняется |
| Глубина | до 64 уровней вложенности — проверяется **до** `JSON.parse`, чтобы не уронить процесс |
| Сбалансированность | скобки должны быть парными, управляющие символы запрещены |
| Схема | известные поля, правильные типы, числовые границы (цена ≥ 0, часов в неделю ≤ 168) |
| Лимиты | длина строк ≤ 4000, элементов ≤ 200, портфолио ≤ 50 работ, ключей ≤ 200 |
| Запрещённые ключи | `__proto__`, `constructor`, `prototype` — защита от подмены прототипа |
| Разметка | `<script>`, `<iframe>`, `javascript:`-ссылки отклоняются; обычный навык «JavaScript: меню, табы» не считается ссылкой |
| Частота | не больше 5 попыток загрузки за 10 минут на пользователя |

Файл принимается только после `/profile upload`; случайный документ в чате игнорируется.
Битый файл никогда не затирает прежний профиль.

### План опроса зависит от категорий

Бот опрашивает только то, что нужно выбранным категориям:

| Выбор | Что запрашивается |
|---|---|
| **не выбраны** (по умолчанию) | один запрос на `/projects` — приходят **все** задания |
| `/categories all` | то же: общий список |
| выбраны категории | запрос на каждую: `/projects?c=37`, `/projects?c=79` |

Категории по умолчанию — **все категории заданий**: пока вы не сузили набор, бот присылает всё,
что нашёл в общем списке.

Посмотреть актуальный план: `/plan` или `node src/index.js plan`.

```
План опроса: 2 запрос(ов) — только выбранные категории.
• https://kwork.ru/projects?c=37 — выбранная категория
• https://kwork.ru/projects?c=79 — выбранная категория
```

Каждый URL — отдельный одиночный GET со своей паузой, поэтому план напрямую влияет на число
запросов за цикл. Жёсткого списка URL больше нет: категории берутся из полного каталога
`config/categories.json`, а источник проверяет только **структуру** запрашиваемого адреса —
`https://kwork.ru/projects` и параметры `c` (категория), `attr` (подраздел), `page` (страница).
Страницы отдельных заданий, API, поиск и профили отклоняются по структуре URL ещё до выхода в сеть.

За загрузку профиля отвечает **только** `data/profiles/`; `PROFILE_FILE` больше не является
запасным профилем. Файл `config/performer-profile.json` остаётся шаблоном для `/profile template`.

### Команда владельца /usage

Показывает расход приложения целиком: пользователи, профили, категории, задания, циклы,
запросы к Kwork, отправленные сообщения, ошибки, расход модели и **токены**:

```
📊 Использование приложения
Подключено пользователей: 2, владелец id 111
Профили загружены: 2 из 2
Свои категории выбрали: 1 из 2
Задания: сейчас в списке 35
С момента запуска: циклов 12, запросов к Kwork 48, страниц 61, карточек 420, новых 96, повторов 324, отправлено сообщений 190
Модель: openai-compatible · deepseek-chat
Модель «openai-compatible · deepseek-chat»: вызовов за сутки 34 из 200, за час 6 из 20, всего вызовов 512
Токены: сегодня 42000 вход / 9800 выход, всего 610000 / 143000 (сумма 753000)
```

В отчёте видно **подключённую** модель (`openai-compatible · deepseek-chat`), а не «heuristic»:
без настроенного провайдера там будет `heuristic` — и это честно, потому что внешних вызовов нет.

Токены берутся из ответа провайдера (`usage.prompt_tokens`/`completion_tokens` у
OpenAI-совместимых, `usage.input_tokens`/`output_tokens` у Anthropic). Если провайдер расход
не сообщает, бот честно пишет об этом и считает только вызовы. `/usage` видит только владелец.

### Долгий опрос и сетевые сбои

Бот использует long polling: Telegram держит соединение открытым до 30 секунд. Таймаут клиента
рассчитывается как «время ожидания + 25 секунд запаса», иначе появлялись ложные `таймаут`.

Если сеть недоступна, в логе видно настоящую причину, а не `fetch failed`:

```
[debug] Сеть недоступна для Telegram, повтор через паузу {"attempt":1,"code":"ENOTFOUND",...}
[warn]  Сеть недоступна для Telegram, повтор через паузу {"attempt":3,"reason":"connect ETIMEDOUT 149.154.167.220:443"}
```

Первые два сбоя пишутся на уровне `debug` (это нормально для мобильной сети), дальше — `warn`.
Пауза растёт экспоненциально до 30 секунд. После успешного опроса счётчик сбрасывается.
Частые `fetch failed` обычно означают, что VPN/прокси рвёт соединение — проверьте сеть.

### Команды в меню Telegram

Команды видны в интерфейсе Telegram (кнопка меню рядом с полем ввода) — их не нужно
набирать вручную. При запуске режима `bot` приложение само вызывает `setMyCommands`.

Тексты команд задаются **только** в `config/texts.json`, двумя наборами:
`commands.telegramMenu` (видят все) и `commands.telegramMenuOwner` (дополнительно к общему
для чата владельца). Публикуются при старте режима `bot` двумя вызовами `setMyCommands`.

```json
// общий набор — видят все пользователи
"telegramMenu": [
  ["start", "запустить бота и получить доступ"],
  ["status", "состояние опроса и хранилища"],
  ["plan", "что именно бот запрашивает"],
  ["profile", "профиль исполнителя"],
  ["categories", "какие категории заданий показывать"],
  ["pause", "поставить опрос на паузу"],
  ["resume", "возобновить опрос"],
  ["help", "список команд"]
],
// расширенный набор — только для чата владельца
"telegramMenuOwner": [
  ["start", "запустить бота и получить доступ"],
  ["status", "состояние опроса и хранилища"],
  ["plan", "что именно бот запрашивает"],
  ["profile", "профиль исполнителя"],
  ["categories", "какие категории заданий показывать"],
  ["pause", "поставить опрос на паузу"],
  ["resume", "возобновить опрос"],
  ["usage", "расход приложения: токены, запросы, пользователи"],
  ["users", "кто имеет доступ к боту"],
  ["help", "список команд"]
]
```

Хотите показать не все команды — перечислите нужные в `config.telegram.menuFilter`:

```json
"telegram": { "menuFilter": ["start", "status", "pause", "resume"] }
```

Описания команд ограничены 256 символами (требование Telegram) и должны быть в нижнем
регистре — это проверяется тестом. Если публикация не удалась (нет сети, старый Bot API),
бот пишет предупреждение в лог, но продолжает работать: команды просто не появятся в меню.

**Меню не публикуется повторно без необходимости.** Отпечаток каждого набора хранится в
`data/telegram-state.json`; при следующем запуске бот видит, что набор не изменился, и не
дёргает `setMyCommands` зря. Если поменяли текст или набор команд — отпечаток изменится, и
меню обновится автоматически.

## Модель анализа

По умолчанию работает **офлайн-эвристика** (`model.provider: "heuristic"`): никакой
нейросети, никаких внешних вызовов, никакого биллинга. Всё считается локально по правилам:

| Что делает | Как |
|---|---|
| Разбирает карточку | встроенный JSON страницы: заголовок, описание, бюджет, категория, заказчик |
| Сопоставляет с профилем | совпадения по `skills`, `positive_keywords`, `negative_keywords`, `excluded_work` |
| Считает риски | `excluded_work`, `backend_requested`, `budget_below_minimum`, `unrealistic_deadline`, `vague_scope`, `unconfirmed_category` |
| Выносит вердикт | «подходит» / «возможно» / «не подходит» / «нужно уточнить» |
| Оценивает деньги | часы по нормативам профиля × ставка `pricing.hourly_rate` |
| Пишет черновик | по структуре из `texts.json` → `proposal.*`, с вашими навыками и портфолио |

Ничего не выдумывается: у каждого утверждения есть источник — «факт из задания», «вывод
приложения» или «неизвестно». Если поля нет, бот пишет `null` и добавляет его в
`missingFields`, а не придумывает значение.

**Нейросеть подключается отдельно и по желанию.** Провайдеры: `openai-compatible` (любой
совместимый API — DeepSeek, Gemini, Groq, OpenRouter, Ollama) и `anthropic`. Модель — надстройка
над эвристикой: она вызывается **когда эвристика решила «возможно» или «нужно уточнить»** —
уточняет оценку, составляет вопросы заказчику, предварительные условия и черновик. Для уверенного
«подходит» черновик пишет эвристика, для «не подходит» модель не вызывается и отчёт идёт без
вопросов, условий и черновика. Факты, риски и цифры (цена/срок) остаются детерминированными; жёсткие блокирующие
риски (исключённая работа, backend) модель не может перекрыть. При любой ошибке (нет ключа,
таймаут, невалидный JSON) анализ молча продолжается на эвристике.

```ini
MODEL_PROVIDER=openai-compatible
LLM_BASE_URL=https://api.groq.com/openai/v1        # бесплатный Groq (~1000 запросов/сутки)
LLM_API_KEY=gsk_...
LLM_MODEL=llama-3.3-70b-versatile
```

**Бюджет запросов.** У бесплатных тарифов есть лимиты на сутки, час и минуту. Бот их считает
и не превышает: при исчерпании остаётся на эвристике и пишет предупреждение вместо ошибки 429.

```jsonc
"model": {
  "usage": { "perDay": 200, "perHour": 20, "minIntervalMs": 6000, "cooldownMs": 60000 }
}
// Модель вызывается для «возможно» и «нужно уточнить»; «подходит» и «не подходит» — эвристика.
```

Расход виден в `/status` («Модель: запросов за сутки 12 из 200») и в `data/model-usage.json`.
Подробнее о выборе провайдера — [docs/MODEL-SETUP.md](docs/MODEL-SETUP.md).

Промпт и логи адаптера лежат в `config/texts.json` → `model.*`, то есть меняются без правки кода.

## Перед первым живым запуском

1. Заполнить `.env` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_USER_ID`).
   Для режима `poll` (без приёма команд) нужен ещё известный chat id: отправьте боту
   `/start` один раз в режиме `bot` либо укажите `TELEGRAM_CHAT_ID`. Иначе `poll`
   откажется запускаться, чтобы не терять уведомления молча.
2. Проверить список запросов: `node src/index.js plan`.
3. Убедиться, что источник разрешён, и **осознанно** включить его — в `config/default.json`:
   ```json
   "source": { "enabled": true, "permission": { "status": "confirmed" } }
   ```
   Без `enabled: true` и `status: "confirmed"` запуск `poll`/`bot` отменяется с ошибкой.
4. `node src/index.js config-check --live` — должен завершиться без ошибок.
5. `node src/index.js bot`.

## Как бот читает страницу Kwork

Задания лежат не в разметке, а во **встроенном JSON** inline-скрипта страницы
(`window.__INITIAL_STATE__...{"wants":[...]}`). Парсер:

1. находит массив `wants` в скриптах (с балансировкой скобок и строк, без регэксп-наивности);
2. берёт поля как есть: `id`, `name`, `description`, `priceLimit`, `possiblePriceLimit`,
   `isHigherPrice`, `max_days`, `category_id`, `categoryLinksIdRu`, `date_create`,
   `date_expire`, `status`, `user.username`, `wantUserGetProfileUrl`;
3. отсутствующие поля оставляет `null` и перечисляет в `missingFields`;
4. дату `2026-10-07 17:05:42` (московское время без зоны) переводит в точный ISO;
5. ссылку собирает из идентификатора (`https://kwork.ru/projects/<id>`) — страница задания
   при этом **не запрашивается**;
6. если встроенного JSON нет, откатывается на JSON-LD и DOM-стратегии.

## Актуальный список задач и очистка индекса

`data/seen-index.json` хранит текущие задачи, а не историю: после каждого полного прохода
задания, которых больше нет в выдаче, удаляются (`source.pruneMissingJobs: true`).

Защита от ложной очистки: удаление выполняется **только** для тех URL, которые в этом
проходе получены и разобраны успешно. Если запрос упал (сеть, 429, пустая страница от
смены разметки) — соответствующие задачи не удаляются, и повторных уведомлений не будет.
Записи старого формата без источника тоже не удаляются.

В логе по каждому запросу видно итог:

```
Запрос выполнен: https://kwork.ru/projects?c=37 | новых задач: 12 | всего задач: 29
```

## Страницы категорий

Страница — это обычный URL того же списка с параметром `page`, поэтому бот обходит её
наравне с остальными URL: `https://kwork.ru/projects?c=38&page=2`.

Как это устроено:

- URL страницы проверяется по структуре: путь `/projects` и параметры `c`, `attr`, `page`
  (только целые числа). `?c=38&page=2&evil=1` или `?c=abc` отклоняются до выхода в сеть;
- каждый URL страницы — **одиночный GET**, между любыми двумя запросами та же случайная
  пауза 240–600 с. Несколько страниц в одном HTTP-ответе Kwork не отдаёт: список целиком
  приходит в одном HTML, поэтому «в одном запросе» технически невозможно;
- проход останавливается сам, если очередная страница пуста.

### Сколько страниц забирать

Глубина берётся из самой выдачи: Kwork отдаёт в payload `pagination.last_page` и `total`,
и бот добирает страницы, **пока сайт сообщает, что они есть**, но не больше
`maxPagesPerUrl` (по умолчанию 6, жёсткий предел 20):

```json
"source": {
  "pagination": { "enabled": true, "maxPagesPerUrl": 6 }
}
```

- `enabled: false` — только первая страница;
- `maxPagesPerUrl: N` — верхняя граница автопрохода;
- если заданий в выдаче больше, чем удалось забрать, бот пишет об этом в итогах цикла:
  `Источник …: в выдаче заявлено 17 заданий, забрано 12 — достигнут предел source.pagination.maxPagesPerUrl=1`.

**Почему это важно.** Kwork показывает по 12 заданий на страницу, а в категории их может быть
больше: в проверке `?c=38` заявлял `total: 17, last_page: 2` — то есть 5 заданий лежали на
второй странице и без автопрохода терялись. Именно поэтому в индексе оказывалось 29 заданий
вместо 35.

Осторожно с множителем: каждая выбранная категория × до `maxPagesPerUrl` страниц — и каждый
URL это отдельный запрос со своей паузой 240–600 с. Проход останавливается сам на пустой
странице или на `last_page`.

## Отображение категорий Kwork (из каталога)

URL `?c=` совпадает с `category_id` в выдаче, поэтому бот показывает название вместо числа.
Полный каталог — `config/categories.json` (7 разделов, 54 категории, 219 подразделов).

| category_id Kwork | Категория |
|---|---|
| 37 | Создание сайта (Новый сайт, Копия сайта) |
| 38 | Доработка и настройка сайта |
| 79 | Верстка (Верстка по макету, Доработка и адаптация верстки) |

Два подраздела «Верстки» (по макету и адаптация) имеют один `category_id = 79`: разделить

## Профиль исполнителя

`config/performer-profile.json` — это **шаблон** для `/profile template` и локального
`dry-run`. Общего профиля у бота нет: каждый пользователь загружает свой через
`/profile upload` (хранится в `data/profiles/<id>.json`). Незаполненные поля
(например, `availability.hours_per_week` и `preferred_deadline_days`) означают, что цена
и срок помечаются предварительными, а не выдумываются.

## Ограничения, которые важно знать

- Разметка Kwork не проверялась на живом сайте: парсер написан под фиксированные fixtures.
  При первом живом запросе возможна смена разметки — тогда бот безопасно приостановится
  и сообщит причину, выдумывать данные он не будет.
- Описание задания берётся только из карточки списка. Если в списке описания нет,
  оно помечается как отсутствующее, а страница задания не запрашивается.
- Дата публикации из относительной подписи («8 минут назад») пересчитывается от времени
  разбора и помечается как производное значение.

## Если приходит «CAPTCHA»

Есть две разные ситуации, и различать их обязательно.

**1. Ложное срабатывание (упоминание вместо проверки).** Большинство страниц подключают
антибот-скрипты и содержат скрытые служебные блоки со словом `captcha`. Раньше детектор
реагировал на само слово и останавливал опрос на нормальной странице. Теперь проверка
считается показанной только при конкретных признаках:

- видимый challenge-виджет (`g-recaptcha`, `h-captcha`, `cf-turnstile`) или его iframe;
- видимое поле ввода кода проверки;
- заголовок страницы/`<h1>` вида «Подтвердите, что вы не робот», «Проверка безопасности»,
  «Attention Required», «Just a moment», «Too many requests»;
- явные тексты блокировки: «доступ запрещён», «вы заблокированы», «слишком много запросов».

Всё остальное (скрипт, скрытый контейнер, слово в коде) — **мягкий сигнал**: он пишется в
логи и в `/status`, но опрос не останавливает. Если после этого остановок стало меньше —
значит, это был именно ложный случай.

**2. Реальная проверка или блокировка.** Тогда источник действительно ограничивает доступ.
Что бот делает: немедленно останавливается, присылает в Telegram диагностику (HTTP статус,
заголовок страницы, маркеры, короткий фрагмент) и **не повторяет запрос**.

Чего бот не делает и не будет: не обходит защиту, не подменяет отпечаток и заголовки,
не использует cookies, прокси, сторонние IP, не решает CAPTCHA автоматически. Это прямо
исключено подтверждённым объёмом доступа.

Легальные способы снизить вероятность реальной проверки:

1. Сократить число запросов: каждая выбранная категория — это отдельный запрос, поэтому
   несколько категорий дают несколько запросов подряд (случайный интервал выбирается перед
   каждым). Если достаточно всех заданий — оставьте `/categories all`: это один запрос на
   общий список `https://kwork.ru/projects`.
2. Уменьшить окно опроса (например, 09:00–20:00) — меньше запросов в сутки.
3. Нажать `/pause` на время и вернуться позже: бот не будет долбить сайт и усугублять.
4. Проверить страницу вручную в браузере: если там действительно проверка — вопрос не в коде.
5. Если ограничение исходит от самого Kwork — согласовать с их поддержкой объём и частоту.
